# GitPier v1.9.0 implementation plan

Status: local development, based on `main` at `c0a1607`. On 2026-11-01 the maintainer requested a local 1.9.0 build; version metadata is now 1.9.0 (32). The public stable release remains 1.8.1 (31). No publication is authorized.

**Goal:** Professional Git Workflows & Repository Health, preserving the native macOS application and existing Git safety boundaries.

**Architecture:** Extend `GitService.swift`, its canonical-worktree FIFO and common-directory coordination. Git's sequencer owns replay and recovery. Repository-owned mutation tasks outlive views; read tasks use generation/selection identities. Health is local-only and read-only.

**Tech stack:** Swift, SwiftUI, AppKit, SwiftPM, macOS 14+, existing Universal packaging and Sparkle trust chain. No new dependencies.

## Phase A: audit and design

| Area | Existing capability | Gap / decision |
| --- | --- | --- |
| History / Diff | Bounded 100-commit pages, filters, cancellable/coalesced reads, background graph, shared commit Diff | Add explicit multi-commit selection and ordered replay review; retain single-click detail behavior |
| Cherry-pick | Single commit through generic reviewed `perform` | Add typed bounded plan, full immutable IDs, clean tracked-state and filesystem identity checks, native sequence |
| Revert | Ordinary generic confirmation; merge-specific review with explicit ordered parent choice | Use the same replay review for ordinary/merge Revert; batch Revert deferred |
| Recovery | Merge completion uses private reviewed Index; Rebase has typed controls and working-file checks; conflict editor exists | Detect sequencer without HEAD markers, fingerprint todo/options/head/abort-safety, typed Cherry-pick/Revert controls |
| Branches / comparison | Native list, search, local/remote refs, comparison with frozen tips, worktree listing | Add local health snapshot, explicit merge target, upstream existence/divergence/activity/worktree occupancy |
| Dashboard / context | Bounded local scans, fetch provenance, facts-based advice, operation links | Reuse existing current-branch signals; expose health facts without extra global scans |
| Operations Center | Shared event reducer, bounded session history, original identity recovery links | Preserve confirmed mutations across view dismissal; unfinished sequences require attention |
| Commit / native files | Precise Index snapshots, partial staging, reusable NSTableView, bounded Diff cache | Preserve; no replacement or new staging implementation |
| Task Workspaces | Identity-bound reads/mutations, optional CLI and existing PTY | Preserve; no changes to credentials, persistence or terminal ownership |
| Distribution | Build/test/UI/performance scripts, Universal ad-hoc packages, documented Developer ID plan | Audit offline only; no production key/certificate/notary/feed actions |

Approaches considered: a separate workflow engine duplicates Git state and is rejected; generic argument dialogs cannot represent ordered review or recovery reliably. The selected implementation adds typed review/state values while keeping native Git execution and existing UI components authoritative.

## Global constraints

- All Git commands remain in `GitPierCore/GitService.swift`, using argument arrays.
- No implicit Fetch/Pull/Push, automatic skip, mainline guessing, reset, force, stash or signing/hook bypass.
- Replay starts only with clean tracked files and no operation. Untracked files remain protected by Git.
- Cherry-pick accepts 1–200 distinct full commit IDs; merge commits are explicitly refused. Revert accepts one commit and requires an explicit parent for merges.
- Reviews bind repository/worktree directories, executable, HEAD, branch, Index stages, operation metadata and Git’s effective replace/graft/shallow object view. Confirmation revalidates inside the existing queue.
- Native metadata remains authoritative after restart. Empty/duplicate replay stops for explicit Skip/Abort; hook/signing failures retain diagnosis.
- Health uses local references, shows observation time / last successful app Fetch or unknown, and never treats inactivity as deletion permission.
- English and Simplified Chinese; shared AppAppearance/overlay scrollbars on all new presentation roots.
- No staging, commits, remote push, tags, releases, production signatures or updates to trust identities.

## Review focus

1. Sequencer remains after hook failure without CHERRY_PICK_HEAD: retain recoverable state and refuse the wrong operation controls.
2. External HEAD, Index, branch, filesystem replacement or executable change: refuse obsolete review before writing.
3. Closing a review / changing page cancels reads only; a confirmed mutation and its Operations Center record persist.
4. Missing upstream or shallow history: show missing/unknown, never a fabricated healthy/merged answer.
5. Large refs/history: bounded queries and stable graph output, reproducible measurements before performance claims.
