# GitPier v1.8.1 Release Preparation Plan

> **For agentic workers:** Use superpowers:executing-plans to execute this plan in the current session. No subagents are authorized. Commit, Push, Tag/Draft, production signing/upload and publication each require explicit maintainer authorization.

**Goal:** Prepare a reviewable 1.8.1 (31) release candidate with bilingual notes, a Universal DMG and reproducible validation evidence.

**Architecture:** Keep ReleaseConfiguration.json as the single version source. Package through the existing release scripts without changing Git, authentication, persistence or the production update trust chain.

**Tech Stack:** Swift/SwiftUI/AppKit, SwiftPM, Sparkle 2, shell/Python release tooling.

**Spec:** Maintainer request to prepare 1.8.1; local release policy `docs/version-development-guidelines.md`, G4–G6 (not distributed).

## Global Constraints

- Preserve com.heisenberg2024.gitpier, macOS 14.0, the existing Feed and public key.
- Preserve installed application, historical assets, user data and Git Index.
- Do not label the candidate Released or reuse an old SHA's CI as the new candidate's CI.
- Do not use production signing keys or create remote release state during local preparation.

## Review Focus

- Version/build must agree between configuration, bundle, DMG filename and notes.
- Complete changes since v1.8.0 must appear in both languages.
- Both main application and CLI must contain arm64 and x86_64 slices.
- Historical assets and installed application must match preflight manifests.
- CI must be identified by full SHA; final version-bump commit still needs its own CI.
