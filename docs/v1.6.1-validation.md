## Remaining safety limits and next versions

Full private review bodies are intentionally not persisted. Known receipts after restart cannot prove omitted bodies or exact positions, so manual platform verification remains necessary. Same-user metadata files are not authenticated against a malicious same-user process. Keychain access can require renewed macOS authorization after ad-hoc upgrades. GitPier is ad-hoc signed without Developer ID or notarization; no claim of universally prompt-free Gatekeeper opening is made.

The journal requires checked parent/file/directory synchronization and the drive-cache barrier described by [Apple's fsync manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html). Unsupported volumes block review writes. Local APFS success and deterministic checkpoint failures establish the tested software boundary; physical power interruption, external drives and network filesystems have not been tested.

Later work may add explicitly protected draft storage, broader live version coverage, GitHub thread resolution or a proven Gitea conditional review API. These do not justify enabling unsafe writes in 1.6.1.

## Actual upgrade environment and cleanup

The first isolated installation under the repository's Documents path reached a valid EdDSA signature and Git busy deferral, then its installer blocked at `renamex_np` while macOS requested Documents privacy access. The original 27 app remained byte-for-byte intact and deep-signed. Only those two test installer processes were stopped. The identical signed old app was copied into the already-private temporary runtime; the same signed feed/DMG then completed replacement and relaunch successfully. System privacy settings were not changed. The preparation tool now puts its installed old app in that private runtime by default, covered by the final path regression. This is an environment limitation for protected install locations, not proof of arbitrary installation-location support.

The upgrade used disposable identities, isolated callback schemes and a new test signing key. It did not install over `/Applications/GitPier.app`, use production Keychain entries or change the default `gitpier://` handler. Final readback still resolves to `/Applications/GitPier.app`; all five protected input hashes and **34** historical asset hashes are unchanged. Final preservation/cleanup records are `.cache/v161/final-preservation.json`, `final-mounts.json`, `handler-final.txt` and `upgrade-evidence/cleanup-result.json`. Evidence preserves hashes/results, not the disposable keys or vault files.
