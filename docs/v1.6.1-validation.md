## Remaining safety limits and next versions

Full private review bodies are intentionally not persisted. Known receipts after restart cannot prove omitted bodies or exact positions, so manual platform verification remains necessary. Same-user metadata files are not authenticated against a malicious same-user process. Keychain access can require renewed macOS authorization after ad-hoc upgrades. GitPier is ad-hoc signed without Developer ID or notarization; no claim of universally prompt-free Gatekeeper opening is made.

The journal requires checked parent/file/directory synchronization and the drive-cache barrier described by [Apple's fsync manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html). Unsupported volumes block review writes. Local APFS success and deterministic checkpoint failures establish the tested software boundary; physical power interruption, external drives and network filesystems have not been tested.

Later work may add explicitly protected draft storage, broader live version coverage, GitHub thread resolution or a proven Gitea conditional review API. These do not justify enabling unsafe writes in 1.6.1.
