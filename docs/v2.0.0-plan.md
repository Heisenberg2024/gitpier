# GitPier v2.0.0 — Production Quality & Native Experience

Local acceptance checkpoint: **Implementation and local acceptance complete; RC gates were open before source submission**. Baseline: `main` at `f6b7e526e19dfd9114259f864cf6c471a06935cf`, verified against the remote on 2026-11-01. Latest released version: v1.9.0 (32), tag `9df9364`. This plan preserves the pre-submission implementation and acceptance record; subsequent same-source CI and local RC manifests are linked by their committed SHA. It is not a publication announcement.

**Goal:** Improve the reliability, clarity and responsiveness of the existing native macOS Git client without expanding its Git or hosting feature set.

**Architecture:** Keep GitService, its canonical-worktree FIFO and common-directory reservations authoritative. Reuse repository-owned mutations, cancellable read tickets, native Git recovery, existing AppAppearance and unified overlay scrollbars. Add focused consistency checks and presentation improvements where evidence demonstrates a problem.

**Tech stack:** Swift, SwiftUI, AppKit, SwiftPM, native Git; macOS 14 minimum; Apple Silicon and Intel; English and Simplified Chinese. Existing pinned SwiftTerm 1.20.0 and Sparkle 2.10.0 remain unchanged.

**Execution:** The primary agent implements and validates the work in place on `codex/v2.0.0-quality`. One read-only independent reviewer was explicitly authorized for this task after the local implementation; the primary agent owns all fixes and validation. Progress and full local logs live in the ignored `.cache/v200/` directory. No automatic staging, commit, push, tag or release.

## Global constraints

- Preserve external and partial staging, file modes, drafts, selection, native hooks and signing.
- Keep native Git sequencer metadata authoritative; revalidate every recovery confirmation.
- Preserve the production Bundle ID, minimum OS, feed, update key and existing distribution scripts.
- Keep Developer ID, notarization, Hardened Runtime production work and publication outside this milestone.
- Use disposable repositories for writes and existing scripts for build and acceptance. Never alter global Git/SSH/shell configuration or inspect unrelated credentials.
- Confirmed mutations survive page/sheet dismissal; cancellable reads reject stale results.
- Retain About as the final Settings tab and reuse the existing scrollbars on both axes and presentation roots.
- Keep modified UI bilingual, keyboard accessible and meaningful without color alone.
- Delay production version metadata changes until the implementation and required local validation are complete.

## Findings and priorities

No confirmed P0 defect has been established at initial audit. A candidate is not marked fixed until its regression demonstrates the original failure.

| ID | Priority | Evidence / reproduction target | Intended resolution |
| --- | --- | --- | --- |
| Q01 | P1 | `snapshot` reads status, copied Index tree, live cached patch and live path list separately. Interleave external staging between those reads. | Publish a coherent review or reject it as changed; never modify the live Index while observing it. |
| Q02 | P1 | `performCommit` queries post-commit status outside the push error handler. Fail/cancel that query after a successful native commit. | Preserve local-success feedback and push-only retry semantics through preparation failures and cancellation. |
| Q03 | P1 | Confirmed: older Diff published after a controlled working-file edit; 32-file selection measured peak 5 Git processes against the existing budget of 3. | Reject changed read results and reuse the existing shared process budget. |
| Q04 | P2 performance | Dashboard `pump` filters and sorts the entire pending queue for every admission. | Measure the scheduler, replace unnecessary sorting while preserving priority and FIFO ordering, compare fixed fixtures. |
| Q05 | P2 UX | History offers per-row checkboxes and a count, but no bulk clear action or full-hash tooltip; detail and replay selection are visually distinct only at the checkbox. | Make selection visible and easy to clear; improve keyboard/focus and hash discovery without changing commit order or graph edges. |
| Q06 | P2 UX / accessibility | Operations use text-only state, name lookup can obscure a worktree, and NSProgressIndicator has an English-only label. Terminal scrollback is already localized and needs no change. | Reuse semantic SF Symbols, show the captured working-tree context and localized accessible labels; preserve cancellation/recovery meanings. |
| Q07 | P2 documentation | Local roadmap still includes trusted distribution in v2.0.0 and is excluded from Git. | Publish an accurate roadmap and evidence-based development/testing records with distribution as a separate later milestone. |
| Q08 | P1 diagnostic privacy | Synthetic authentication-header/JSON/named-secret test produced seven failed assertions against URL-only redaction. | Expand the existing output redactor before retaining bounded historical diagnostics; no credential reads or storage policy changes. |
| Q09 | P2 validation | A final performance run recorded a 0.080 ms commit: the rendered page preceded asynchronous activation, and the existing driver accepted a guarded no-op. | Wait for activation and canCommit, then require actual native HEAD advancement matching the model checkpoint. Reject the invalid commit/network segment. |
| Q10 | P2 review | Independent review identified unconditional restoration of an operation error after final refresh. A controlled native Close during the blocked refresh reopened the Sheet on the original implementation. | Track error-dismissal generation and retain operation diagnostics independently; native RED/GREEN confirms no reopening and preserved historical cause. |

A follow-up retention regression confirmed that 4,096 Swift Characters alone can retain a 65,546-byte combining grapheme. Diagnostics now also cap UTF-8 retention at 16 KiB, trim incomplete scalar encodings and keep redaction before truncation. The focused three-case diagnostic suite passed; the final cumulative suite passed 1,065 cases and the Universal candidate was rebuilt after this amendment.

## Review focus

1. External Index changes between commands must never yield a misleading reviewed commit tree or erase partial staging.
2. A successful local commit remains a success even when subsequent status collection, push preparation or transport fails/cancels.
3. Rapid selection/edit/repository changes must not publish late Diff results or create unbounded work.
4. Priority promotion and cancellation must retain scheduler fairness and occupied slots until actual completion.
5. Worktree/operation context, warnings and selected counts must remain readable through narrow windows, both languages and increased contrast without relying on color.

## Acceptance and limitations

The acceptance record must distinguish Core automation, real disposable Git, native UI, real account/server validation, hardware and distribution. A green command does not resolve a missing high-priority requirement. No live-service writes or private authentication tests are authorized by this plan. Independent review is required for high-risk Git consistency changes; the user explicitly authorized one read-only reviewer for this task. Further delegation still requires applicable explicit authorization. Self-review and regression evidence do not count as that independent review.
