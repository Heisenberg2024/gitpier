### Performance-driver readiness correction

The first final-byte-bound run returned exit 0 while recording a **0.080 ms commit** and near-zero network timings. That commit/network segment was rejected: the existing driver waited only for a rendered page after switching repositories, then called the model while its activation could still be incomplete. A disabled commit returns early through the existing safety guard.

The driver now awaits model activation and `canCommit`, then requires native HEAD to advance and match `model.lastCommit`. A `commitHeadAdvanced = 1` counter is emitted only after that assertion (verified in the final rerun). This changes acceptance tooling, not normal product behavior. The 134 final Core inputs and all UI/operations sources remain unchanged; the isolated bundle was rebuilt and the guarded full fixture passed after this correction. Earlier refresh/Diff/history/RSS measurements precede that invalid segment and remain separately reported; the rejected 0.080 ms value is never a speedup claim.
