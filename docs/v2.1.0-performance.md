# v2.1.0 performance follow-up

**Development / Unreleased.** Local validation, 30 matched native runs and full source CI are complete. The development candidate is 2.1.0 (35). The stable release is v2.0.1 (34).

## Changes and retained safety

- Resolve the current remote-check record/staleness once per native render and reuse help text for tooltip/accessibility/toolbar. Observed-object updates, localization and current dates remain live on subsequent renders; no persistent Git-state cache.
- Coalesce forced refresh/reconciliation notifications inside one synchronous workspace actor turn. Explicit invalidation still publishes immediately. Priority, generation, cancellation ownership, per-worktree/common-directory queues and the three-worker budget remain unchanged; a cancelled worker keeps its slot until it exits.
- Read the existing complete Push configuration once per validation phase. Derive that phase's URL configuration/custom-transport fields from it and resolve the native effective Push URL once. The final configuration/authentication/transport fingerprint follows all local source/URL/remote/alias queries. Preserve root/Git/common-directory device/inode checks, exact HEAD/branch/conflict/native-operation checks, original remote/ref/URL proof and verification before/after remote reads. No cross-phase observation reuse, automatic Push, Force, repeated Commit or Index/Hook/signing/TLS/SSH bypass.
- A real-Git process-budget test retains all three fresh complete fingerprints and all three native `ls-remote --get-url` alias checks. Effective URL resolutions fall **6 → 3**, extra standalone URL configuration reads **7 → 0**. Native default mapping and bool checks stay enabled. Multiple effective destinations/custom transports remain manual; native empty-URL list resets and mixed-case remote names remain supported.

## Matching method

Same arm64 machine, 14 logical CPUs, macOS 27.0.1 (26A434), Apple Git 2.54.0, Swift 6.4, Universal Release. R4 matches all 320 earlier product/test/tool inputs; preserved formal v2.0.1 matches 316 inputs from Tag `0c3bcd9`. Isolated copies change only Info.plist runtime identity/names/URL registration and ad-hoc root signatures; unsigned main payloads match their original app.

Unchanged existing scripts/fixtures: 10/50/100 physical repositories plus one linked Worktree and two unavailable entries, 1,000 commits per clone and 10,000 untracked files in one repository. Each case uses a fresh AppStore/cache in a warmed native process; timings exclude fixture creation/process launch. Organization switching is measured during a refresh; this is not a repository-open/first-Diff benchmark. General operations use real disposable local remotes, commits advance HEAD, warm Diff foreground misses remain zero. No builds/Core/other GUI acceptance ran during timing. Diagnostic Trace2/native-sampling trials are excluded.

R4: six workspace pairs alternating B/C,C/B (12 runs), plus three general pairs B/C,C/B,B/C (six runs). Formal v2.0.1: three separate workspace and three separate general pairs (12 runs). B is the named baseline, C the same optimized executable. **No historical samples or the two reference groups are pooled.**

Workspace P50 is the median and P95 is nearest-rank: with six/three samples, P95 is the maximum. General P50 is the median of per-run medians; other per-run P95 summaries are retained in JSON and are not pooled percentiles. Push has one timed sample per invocation; its table below explicitly shows the median and maximum across three runs. Push includes transfer and post-operation refresh, so these numbers do not isolate preflight latency. CPU totals include fixture preparation; RSS is cumulative process peak, not current retained memory.

## Corrections and limits

Independent review caught a Push validation gap before commit. A real Git wrapper changed the custom transport during remote enumeration and recorded an unexpected Push attempt. Moving the final configuration, fingerprint, transport and URL identity checks after local resolution closed the gap.

The empty URL test assumed that Git always resets an empty entry. The first CI run on `4842a9d` recorded one assertion failure among 1,126 cases. Apple Git 2.39.5 emits a blank first line followed by the valid target. Git 2.54.0 returns only the valid target. The corrected test requires verification for one URL and rejects checkpoint creation for the blank plus valid output. Unexpected output fails the test. The same reviewer accepted the correction. The 28 local Push tests and the complete suite on Apple Git 2.39.5 passed. The failed report remains archived locally. [CI 41533969416](https://github.com/Heisenberg2024/gitpier/actions/runs/41533969416) · [CI 41585646442](https://github.com/Heisenberg2024/gitpier/actions/runs/41585646442)

The first native driver sent Debug-only scopes to Release and therefore ran the default UI/PTY suite. Two default suites passed 218.808/217.598 s; neither proves the requested special scope. The second was redundant and a third fallback was stopped 29.417 s in. Actual coverage was relabeled and the driver now requires each scope's completion marker. Debug-only Branch Health and retry scopes were subsequently exercised with Debug.

An actual Debug retry-cancel then exposed the existing fixture marker/diagnostic race: cancellation could precede emission of the required synthetic stderr. The fixture now emits the diagnostic before publishing readiness, with all original cancellation/resultUnknown/remote/local Hash/target/no-duplicate-Commit assertions intact. Both languages pass after rebuilding; the failed English raw JSON is preserved. Release's 115 entries remain byte-identical because the edit is wholly Debug.

Small, warmed native samples do not establish statistical significance, cold-launch performance, long-term memory behavior or all hardware/service behavior. Private hosting/credentials, Intel/macOS 14 hardware, full VoiceOver/system accessibility settings and production self-update remain outside this follow-up; earlier boundaries remain in [v2.1.0 validation](v2.1.0-testing.md). No process-limit increase, stale-state delay, new dependency, release, production signing, notarization or installation.
